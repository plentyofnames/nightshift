# Code review, 2026-11-08: Night Shift and Eye of Providence

Correctness, usability, interface quirks, streamlining. Ten reviewers each read a slice of the three codebases (Night Shift, Rotary Club, Eye of Providence), ran the tests, and wrote throwaway probes against the modules and the stand-ins; the highest-severity claims were then checked a second time against the code. The Rotary Club part is in the firmware repo: `bcr32-fw/docs/review-2026-11-08.md`.

Baseline: Night Shift 182 tests pass, Eye of Providence 33, Lilypad 32; the firmware's whole Mac suite passes, both m303 oracles match (124/124, 305/305), `make check-editor` 31/31. Nothing was modified, no port was opened, nothing went to a unit.

Severity: **high** = wrong result or data loss in ordinary use; **medium** = wrong result in a reachable case, or a flow that misleads; **low** = edge case, quirk, or cleanup. "confirmed" = reproduced with a probe or traced end to end; "likely" = read, not run.

## Night Shift

**Fixed the same day (uncommitted at the time of writing; 187 tests pass):** Fix-first items 1–10 and the "Also medium" list below, except the number-box redraw (that fix belongs in Lilypad's `dom.js`). In short: "Remove them" gets the names; names are trimmed on read; keep marks live on the scene (`preset.marks`, in the project file as `marks`, older projects' marks go onto every scene); Save to flash reads the module first; the replace-your-changes question survives a reload (`nightshift.edited`); a Get into the example makes it a kept patch; the BCR32 link treats a same-page STATE as a reload and reads its image once Night Shift is free; the EC4 link trusts the stored fingerprint only after a Send in this session; the client survives a throwing transport and a late timer; bytes with bit 7 set are masked on open and reported; level-type triggers on a gate jack are flagged; MPE strides count the Y jack; a channel past 15 can't take the view down; rate selects show off-list values; a voice's or kit's channel change moves its players; number boxes drop invalid text; busy says so; MIDI blocked / silent FH-2 / no Web MIDI are told apart.

**Verdict.** Sound architecture, well tested where it counts. The dumps are the truth, `derive()` recomputes everything, every edit is a checked list of field changes with its inverse (a fuzz of 88 random edits undone and redone restored config, preset and names byte for byte), the layouts are checked field by field against Expert Sleepers' own encoders and rewritten byte for byte, and the controller byte layouts match both firmwares' decoders. Nothing structural needs to change. The faults are at the seams: a per-scene fact kept per project, a decision keyed on "can I undo" instead of "does it differ", a verify step that compares a trimmed name with a padded one, and one call that forgot an argument.

### Fix first

1. ✅ **`js/app.js:1117` "Remove them" removes the BCR32's CCs too** (high, confirmed). `tidyEc4` calls `strayMappings(state.view, ec4Model())` without `state.names`, while the tab's count at `app.js:1883` passes them, so `onBcr32()` (`ec4/pages.js:683`) never excludes BCR32-only settings in the removal path. Euclid pulses on the BCR32 only plus one truly stray CC: the tab says "1 CCs on no page", the dialog lists 2, both go; the BCR32 knob is dead until it gets a CC again and a Store. Fix: pass `state.names`; make `names` a required parameter. **Fixed.**
2. ✅ **`js/fh2/layout.js:59-63` + `js/fh2/client.js:136-139`: a renamed config or scene fails the post-Send check** (high in code, confirmed with the stand-in; not tried on the module). `name16.read` returns the 16 space-padded characters; every UI edit stores a trimmed name (`app.js:415`, `app.js:512`, `ui/settings.js:22`). After a rename, Send installs correctly, `verifyInstall`'s `diff` reports `name` as off, `app.js:695-699` shows "Sent, but the FH-2 holds something else for config: name" and drops the sync mark. Fix: trim in `name16.read` (write keeps padding); adjust `test/official.js:57`. One-minute check on the FH-2: rename a scene, Send, watch the status. **Fixed**; the one-minute check on the module is still worth doing.
3. ✅ **`js/patch/edit.js:137`, `js/patch/derive.js:159-167,185`: the `keep:lfo:n` / `keep:level:n` marks live in `names` (per project) but the values they point at live in the preset (per scene)** (medium, confirmed). `addLfo(5)` in scene A makes scene B show an LFO on jack 6 drawn flat, and "Level 0"; `clearJack` in B deletes A's mark. Fix: marks per scene (a `marks[]` beside `scenes` in the project, passed to `derive`). **Fixed.**
4. ✅ **`js/app.js:942-961`: Save to flash trusts a possibly minutes-old read** (medium, confirmed). Nothing re-reads the module between the last Get/Send and Save; the panel, a program change or the official tool can have loaded something else while the mark still says "same". Save then stores that into the slots the dialog named, and `heldOnFlash` records this scene's fingerprint as saved. Fix: pull config and preset and compare before `saveToFlash`; refuse with "The FH-2 holds something else: Send first". **Fixed.**
5. ✅ **`js/app.js:570-577`: `dropUnsent` asks only when `history.canUndo`** (medium, confirmed). After a reload the history is fresh, so Open…, a dropped `.syx` or Example replace unsent edits without a question, and 300 ms later `store()` overwrites the kept copy. Fix: key on `state.unsent` alone. **Fixed.**
6. ✅ **`js/app.js:195, 619-637, 1818-1822`: after the example, nothing is kept again** (medium, confirmed). `store()` returns while `state.from === 'example'`; a Get into the example leaves `from` as it is, as does every edit after it. Open example, Get the module's patch, work an hour, reload: gone. Fix: a Get or first edit switches `from`; or show "not kept" in the mark while it applies. **Fixed.**
7. ✅ **`js/patch/derive.js:342-349`: level-type triggers on a gate jack raise no problem** (medium, confirmed). `gateFriendly` returns true for every trigger, though `edit.js:403` and the dialogs say Velocity trigger/gate, Envelope and Velocity need a CV jack, and a voice's Velocity gate on a gate jack is flagged. Fix: carry `typeIndex` into the port entry (line 49) and test it. **Fixed.**
8. ✅ **`js/rotary/link.js:48-57`: a same-page T tap on the BCR32 drops the RAM edits and the link never notices** (medium, confirmed in the firmware's code; two reviewers found it independently). `ctl_select` → `select_page` re-decodes the page even when it hasn't changed and sends a STATE with the same page; `_state` sees `moved = false`, keeps `edited`, emits nothing. The knob sends its stored CC/name until the page changes or Store. Fix on both sides: the firmware should not reload a page that didn't change (see the firmware review), and the link should clear `edited` on any unsolicited STATE. The EC4 link has the same shape (`ec4/link.js:72-81`); controlfrog's behaviour on re-picking the current group was not checked. **Fixed on Night Shift's side** (`_state` treats an unsolicited same-page STATE as a reload); the firmware side is with the bcr32-fw fixes.
9. ✅ **`js/app.js:1541`: a BCR32 that links while Night Shift is busy never gets its image** (medium, confirmed). `linkBcr32` reads it only `if (!state.busy)`; nothing reads later except Send; `showOnBcr32` returns on `!img`. Plug in during a Get, Send or calibration walk and the link is dead. Fix: read when busy clears. **Fixed.**
10. ✅ **`js/ec4/link.js:128-139`, `js/app.js:1301`: the EC4 link trusts the fingerprint saved in the project file** (medium, confirmed by reading). `stored = !ec4Unstored()` compares against what the *project* says was last sent, not the unit. A project opened on another computer, or an EC4 Lilypad rewrote: the EC4 shows its EEPROM's cells, the tab shows Night Shift's, no "Not stored", nothing corrects until a cell changes. Fix: read setup 15's name at link-up and show it, or treat `stored` as false until a Send in this session. **Fixed** the second way: the EC4's RAM gets the cells until a Send in this session.
